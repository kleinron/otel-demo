# Expected alarms for scheduled spikes

Use this table after a run to check which alert each spike fired. Spikes run daily at 10:00, 12:00, 14:00, and 20:00 UTC. Each spike lasts 20 minutes. The rate multiplier is set by the load generator.

The first spike that actually runs after deploy is a baseline: traffic only, no fault. The expectation is that no alert fires. Record what actually happens.

Every later spike is paired with a delay or timeout fault at 100% probability on one operation. The fault starts 2 minutes after the spike starts and lasts 15 minutes. The checkout fault lasts 20 minutes.

Leave the last two columns blank until the run, then fill them in.

## Notes

- Fault windows must be longer than the alarm's evaluation window. A 2-of-3 five-minute p99 alarm needs at least 10–15 minutes of the breaching condition.
- The day-2 12:00 UTC spike is the saturation-sized one. Expect CPU saturation visible in metrics in addition to the paired alarm, `shop-checkout-p99-latency`.
- Informational alerts must not page.
- Thresholds remain initial values.
